# 架构与数据流

这是一个本地示意用的化工厂数字孪生预览，不是现场控制系统，也不是热力学仿真。

## 进程

`npm run dev` 由 `scripts/dev.mjs` 拉起两个 Node 进程，不使用 bash 专用语法：

- Vite，默认 `http://127.0.0.1:4317`，提供 React 界面。
- `server/index.ts`，默认 `http://127.0.0.1:4318`，用 Node 内置 `node:http` 提供 SSE。

浏览器只访问 4317。Vite 把 `/api` 反代到模拟服务，所以页面不直连另一个源。

## 数据闭环

1. 模拟服务保存 `seq`、负荷 `load`、冷却故障开关和应力 `stress`。
2. 每 1.5 秒调用纯函数 `computeReadings({ seq, load, stress })`。故障打开时 `stepStress` 把应力推向 1，关闭时推向 0。
3. SSE 帧包含 `seq`、墙钟 `timestamp`、`simulated: true`、免责声明、暂停标志、负荷、故障、应力，以及每台设备的温度、压力、流量、液位和状态。
4. 浏览器 `EventSource` 接收帧。界面数字和短趋势来自这些帧。Three.js 场景只读同一帧的流量来驱动管线 UV 和实例粒子，不把 React 状态写进网格。
5. 负荷滑块、故障演练、暂停和重置走 `POST /api/control`。这个接口只改本地模拟器。`src/sim/adapter.ts` 把只读遥测和本地演练分成两个类型，避免被当成现场写指令。

同一组 `seq / load / stress` 永远得到同一组读数。时间戳是发送时刻，不参与计算。

## 断流

超过 4.5 秒没有新帧就标记为过期，保留最后一帧数字，并把流动速度降为 0。手动断开不会自动重连，也不会把旧值显示成实时。暂停时服务继续发心跳，但 `seq` 不增加、`paused` 为真，流动停止。

## 场景

- 单位：米。Y 向上，X 向东，-Z 向北。
- 场地约 116×90 m，是示意图，不是测绘。
- 工艺层标高 0 / 13 / 26 m。展开时上层整体抬高，管线端点按锚点重算，避免悬空。
- 设备是带 `userData.assetId` 的 Group。列表和射线拾取使用同一组稳定位号。
- 10 条有向管线用正交拐角加圆角，再生成 `TubeGeometry`。粒子是一个 `InstancedMesh`。

## 与教程示例位号的差异

教程链是 `TK-101 → P-101 → E-101 → T-201 → T-202 → E-301 → V-301`，回流 `V-301 → T-202`，产品 `T-202 → TK-102`。

已确认的画面位号不同。本项目保留画面位号，并在清单里写明对应关系：

| 本项目 | 角色 | 教程示例 |
| --- | --- | --- |
| TK-201 | 原料罐 | TK-101 |
| P-401 | 进料泵 | P-101 |
| E-101 | 原料预热器 | E-101 |
| T-101 | 主精馏塔 | T-201 |
| T-102 | 汽提塔 | T-202 |
| CW-301 | 轴流冷却机组 | E-301 |
| V-301 | 回流罐 | V-301 |
| TK-202 | 中间罐 | TK-102 |
| T-103 / T-104 | 吸收塔 / 放空塔 | 画面增补 |
| CW-302 / PR-401 | 冷却水池 / 管廊 | 画面增补 |

有向链是 `TK-201 → P-401 → E-101 → T-101 → T-102 → CW-301 → V-301`，回流 `V-301 → T-102`，产品 `T-102 → TK-202`，另加冷却上水 `CW-302 → CW-301` 和尾气 `T-103 → T-104`。冷却故障作用于 CW-301、T-102、V-301。

界面因此是 12 台可点设备，不是教程里的 8 台，也不是定稿列表里的 10 行。多出来的 E-101 和 V-301 是为了让教程链上的预热器和回流罐真正存在。
